Lab 42 - CRM smoke through the Traefik Ingress
Captured 2026-08-21. Bearer tokens redacted; no password appears here.
Transcribed from the session terminal.

The hostname is not in DNS. Requests go to loopback on the k3d load balancer
port and Traefik routes on the Host header.

  $H = "Host: crm-api.training.example.test"
  $B = "http://127.0.0.1:8088"

=== Probes, anonymous ===

$ curl.exe -s -w '\n<- HTTP %{http_code}' -H $H "$B/actuator/health/readiness"
{"status":"UP"}
<- HTTP 200

$ curl.exe -s -o NUL -w '%{http_code}' -H $H "$B/api/customers"
401

Readiness answers anonymously; the customer API does not. Only
/actuator/health, /actuator/health/readiness and /actuator/health/liveness are
permitted without a token. env and beans are not exposed.

=== Login ===

$ curl.exe -s -X POST "$B/api/auth/login" -H $H \
    -H "Content-Type: application/json" \
    -H "X-Correlation-Id: lab-request-001" \
    -d "@login.json"
{"role":"AGENT","tokenType":"Bearer","accessToken":"<redacted>","username":"agent1"}
<- HTTP 200

httpBasic and formLogin are disabled in this build, so every /api/customers
route needs the token from this call. On Windows PowerShell the JSON body is
passed from a file because PowerShell 5.1 mangles inline quotes handed to a
native executable.

One 200 covers the whole path: Traefik, the Service, the pod, JPA, the crm
role, host.k3d.internal to the host-published Postgres port, the crm_lab42 database,
Flyway's schema, and the fixtures FixtureLoader seeded at startup.

Both pods carry the ReplicaSet hash 694dbd5685, the same one that has served
since the first deploy. Scaling changes a count on the existing ReplicaSet; it
does not create a new one and does not add a revision. Compare with set image,
which changes the pod template and therefore does both.
