Timestamps trimmed to keep the lines readable; the full run keeps them.

Request F sends no header and still logs corr=lab-request-001. That is the
filter's default for a missing header, not a leak from request A; the filter
puts a value on every request and clears in finally. Experiment 5 in
03-failure-experiments.txt shows what an actual leak looks like.

The controller WARN on request E has cust= and op= empty. The rejection happens
at the API edge before the service opens its MDC scope, so only correlationId
is set; the customer id travels in the message instead.

No line carries Amina, Ravi, Sam or an address. cust= is the customer id and
nothing else.

FORBIDDEN-FIELD GREP

  grep -nE "Amina|Ravi|@example\.com|password|Bearer " notes/screenshots/lab-20/*.txt

Five hits in this file, all of them inside the HTTP response bodies above. The
API returns fullName and email by design; the rule is that they never reach a
log line. The same grep over the console lines only is clean:

  grep -nE "c\.n\.crm" notes/screenshots/lab-20/*.txt | grep -nE "Amina|Ravi|Sam|Dana|@example\.com"
