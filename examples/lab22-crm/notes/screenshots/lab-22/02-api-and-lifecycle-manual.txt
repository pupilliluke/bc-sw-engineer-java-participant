Lab 22 API and lifecycle manual session, captured 2026-08-05
Windows, Temurin JDK 21.0.4, Maven 3.9.9, examples\lab22-crm

App on port 8080. Every request carries X-Correlation-Id: lab-request-001.
Started with spring-boot:start and stopped with spring-boot:stop rather than
Ctrl+C, because the plugin forks the JVM and a console signal does not reach
it from a background shell. Both go through the same graceful context close.

  mvn -B spring-boot:start

POST of Amina lands as a duplicate; it is in section 3 and in experiment 3.

Validation is still at the controller edge, so the blank-name POST never
reaches CustomerService and the WARN comes from CustomerController. The error
strings still say customerId and fullName; those are lab 20 reason codes in
docs/logging.md and are not the JSON field names.


4, SHUTDOWN

  mvn -B spring-boot:stop

  2026-08-05 17:08:45,360 INFO  [RMI TCP Connection(4)-127.0.0.1] c.n.crm.service.CustomerService corr= cust= op= - CustomerService shutting down

One @PreDestroy line on the graceful stop. The singleton is one instance for
the whole context, so the store and the two counters are shared across every
request thread above.
