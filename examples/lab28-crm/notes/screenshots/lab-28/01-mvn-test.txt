THE THREE

missingTokenIs401 calls GET /api/customers/CUS-1001 with no Authorization header
and then again with Bearer lab.agent1.ADMIN.deadbeef. Both are 401. The second
is a well formed token with a role that would pass the matcher, refused on the
signature.

agentCanReadCustomerButNotAdmin posts agent1/agent1 to /api/auth/login, pulls
accessToken out of the response, reads CUS-1001 with the Bearer header and
asserts Amina Khan and ACTIVE, then calls /api/admin/ping with the same token and
asserts 403.

adminCanPing does the same login as admin1/admin1 and asserts 200 with role
ADMIN on /api/admin/ping.

All three go through /api/auth/login rather than @WithMockUser. That covers the
token format, AuthController and JwtAuthenticationFilter as well as the matchers.
@WithMockUser would put the authority straight into the SecurityContext and skip
all of it, and the stub token would never be parsed.

MOCKMVC AND 403

MockMvc reports the 403 directly. It does not run the Boot error dispatch, so
the /error permitAll rule is not exercised here and the agent to admin case has
to be checked on live Tomcat as well. That run is in 02-auth-demo.txt.
