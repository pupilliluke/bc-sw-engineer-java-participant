WSDL

  curl -s http://localhost:8080/ws/customers.wsdl

  <wsdl:definitions ... targetNamespace="http://northstar.com/crm/customers">
  <wsdl:portType name="CustomersPort">
    <wsdl:operation name="GetCustomer">
  <soap:address location="http://localhost:8080/ws"/>

The operation name GetCustomer is not written anywhere. DefaultWsdl11Definition
pairs GetCustomerRequest with GetCustomerResponse from the xsd and strips the
suffixes. soap:address shows the real host because setTransformWsdlLocations is
true.


SOAP getCustomer CUS-1001

  curl -s -X POST http://localhost:8080/ws -H "Content-Type: text/xml; charset=utf-8" --data @requests/get-customer.xml

  <SOAP-ENV:Envelope xmlns:SOAP-ENV="http://schemas.xmlsoap.org/soap/envelope/"><SOAP-ENV:Header/><SOAP-ENV:Body><GetCustomerResponse xmlns="http://northstar.com/crm/customers"><customerId>CUS-1001</customerId><name>Amina Khan</name><email>amina.khan@example.com</email><status>ACTIVE</status></GetCustomerResponse></SOAP-ENV:Body></SOAP-ENV:Envelope>

No Security header on the request and it still succeeds. UsernameToken is not
wired on the timed path.


REST GET CUS-1001

  curl -s http://localhost:8080/api/customers/CUS-1001

  {"id":"CUS-1001","name":"Amina Khan","email":"amina.khan@example.com","status":"ACTIVE"}

Same customer, same service. The wire names differ: customerId in the xsd, id in
the Java domain. CustomerSoapMapper is what bridges them.
