THE SIX

getSeededCus1001 asserts id, name and status on CUS-1001.
duplicateCreateRejected constructs the service over a fresh
InMemoryCustomerRepository, so CUS-1001 is already seeded and the first create
is the duplicate.
listReturnsSeedsAndCreated reads 2 seeds, creates CUS-1003, reads 3.
activateRaviFromProspect moves CUS-1002 PROSPECT to ACTIVE and reads it back.
illegalTransitionRejectedAndStatusUnchanged asks CUS-1001 for ACTIVE to
PROSPECT, catches IllegalStateException, then asserts the status is still
ACTIVE.
closedIsTerminal moves CUS-1002 to CLOSED, then asks for ACTIVE and gets the
same exception.

Each test builds its own repository, so a create or a status change in one
cannot change what the next one sees.

No @SpringBootTest anywhere in this suite. CustomerService takes the repository
through its constructor, so the rules test without a container.
