500 is the Boot default for the unhandled IllegalStateException. This lab adds
no @ExceptionHandler, so there is no 409 and the body carries no message.


WHAT THE DATABASE SAW

show-sql is on. The happy path:

  Hibernate: select a1_0.id,a1_0.balance,a1_0.customer_id,a1_0.type from account a1_0 where a1_0.id=?
  Hibernate: select a1_0.id,a1_0.balance,a1_0.customer_id,a1_0.type from account a1_0 where a1_0.id=?
  Hibernate: insert into transaction_log (amount,created_at,from_account_id,to_account_id,id) values (?,?,?,?,default)
  Hibernate: update account set balance=?,customer_id=?,type=? where id=?
  Hibernate: update account set balance=?,customer_id=?,type=? where id=?

The forced failure:

  Hibernate: select a1_0.id,a1_0.balance,a1_0.customer_id,a1_0.type from account a1_0 where a1_0.id=?

One select and nothing else. No update was ever sent. Hibernate flushes at
commit, the transaction rolled back first, so the debit never reached the
database at all. accountRepository.save on a managed entity does not issue SQL
where it is called.

insert into transaction_log appears once for the happy path and not for the
failed attempt.

The balances themselves are asserted in TransferServiceTest rather than curled.
The starter exposes POST /api/transfers only, with no read route, so there is no
HTTP way to display a balance in this build.
