All five, plus the override ladder from step 6. Every temporary edit is

1, PROD WITHOUT DB_PASSWORD

  mvn -B spring-boot:run "-Dspring-boot.run.profiles=prod"

  2026-08-07T15:41:01 INFO  com.northstar.crm.CrmApplication : The following 1 profile is active: "prod"
  2026-08-07T15:41:04 ERROR com.zaxxer.hikari.HikariConfig   : Failed to load driver class org.postgresql.Driver from HikariConfig class classloader
  BeanCreationException: Error creating bean with name 'dataSource' defined in class path resource [org/springframework/boot/autoconfigure/jdbc/DataSourceConfiguration$Hikari.class]
  [INFO] BUILD FAILURE

The profile is confirmed active before the failure, so this is prod refusing to
start and not a bad command line. dev and test start normally on H2.

No APPLICATION FAILED TO START banner appears. Boot has no failure analyzer for
a missing driver class, so the output is the BeanCreationException and the Maven
BUILD FAILURE instead.

The placeholders are not what stops it. With the postgres driver temporarily on
the classpath, so the datasource can build, prod starts with nothing set:

  Started CrmApplication in 4.766 seconds
  profiles=[prod] apiBaseUrl=http://localhost:9090 connectTimeoutMs=2000 apiKeySet=true

apiKeySet is true because the binder put the literal string ${NORTHSTAR_API_KEY}
into the field. Boot's @ConfigurationProperties binder ignores placeholders it
cannot resolve, so nothing failed and nothing warned. Driver removed again after
the measurement; the classpath is H2 only, as the lab expects.

Also measured on that classpath, all with no env vars set:

  password: ${DB_PASSWORD}, no default                    binds the literal
  password: ${DB_PASSWORD:}, empty default                same
  @Validated with @NotBlank on apiKey                     passes, literal is not blank
  same placeholder on the int connect-timeout-ms          APPLICATION FAILED TO START

The leniency is type specific. The literal survives as a String and only fails
where it has to convert, which is why none of the three secrets can raise it and
the int does.

5, NO PROFILE SET

  java -jar target/lab26-crm-0.0.1-SNAPSHOT.jar

  No active profile set, falling back to 1 default profile: "default"
  profiles=[] apiBaseUrl=http://localhost:9090 connectTimeoutMs=2000 apiKeySet=false

The banner and getActiveProfiles both say no profile, but application-dev.yml
does load. Confirmed by temporarily putting api-base-url http://dev-probe:9090
in application-dev.yml and running with nothing set:

  apiBaseUrl=http://dev-probe:9090

Same value as an explicit -Dspring.profiles.active=dev run. So
spring.profiles.default: dev in the base file works, and dev is a default
profile rather than an active one, which is why it does not show up in the
banner. Marker removed afterwards.

Blast radius for a real deployment: an unset profile does not get prod. It gets
dev, with dev's H2 URL and DEBUG logging, and the postgres URL that would have
stopped startup is never read.


6, OVERRIDE LADDER (step 6, full path)

Measured on northstar.integration.connect-timeout-ms under the test profile.
Each run keeps the previous run's setting in place.

  java -jar ... --spring.profiles.active=test
  connectTimeoutMs=100

  NORTHSTAR_INTEGRATION_CONNECT_TIMEOUT_MS=9999 java -jar ... --spring.profiles.active=test
  connectTimeoutMs=9999

  NORTHSTAR_INTEGRATION_CONNECT_TIMEOUT_MS=9999 java -Dnorthstar.integration.connect-timeout-ms=1234 -jar ... --spring.profiles.active=test
  connectTimeoutMs=1234

CLI beats env beats profile YAML beats base YAML at 2000. The env var name is
the relaxed-binding form of the property, upper case with dots and dashes as
underscores.
