Lab 26 failure experiments, captured 2026-08-07
Windows, Temurin JDK 21.0.4, Maven 3.9.9, examples\lab26-crm

All five, plus the override ladder from step 6. Every temporary edit is
restored and the suite is green at 1 in 01-mvn-test.txt, captured after these.


1, PROD WITHOUT DB_PASSWORD

The starter pom has no postgresql driver, so the first prod run stopped on

  Caused by: java.lang.RuntimeException: Failed to load driver class org.postgresql.Driver in either of HikariConfig class loader or Thread context classloader

which is the driver, not the secret. application-prod.yml declares a postgres
URL, so org.postgresql:postgresql runtime was added to the pom and the rest of
this experiment runs against the declared config with no overrides.

With the guard temporarily off (@Profile("prod") switched to "never"):

  java -jar target/lab26-crm-0.0.1-SNAPSHOT.jar --spring.profiles.active=prod

  Started CrmApplication in 4.766 seconds
  profiles=[prod] apiBaseUrl=http://localhost:9090 connectTimeoutMs=2000 apiKeySet=true

prod started with no env vars set. apiKeySet is true because the binder put the
literal string ${NORTHSTAR_API_KEY} into the field. Boot's
@ConfigurationProperties binder ignores placeholders it cannot resolve, so
nothing failed and nothing warned. A blank DB_PASSWORD would have reached the
pool the same way.

Guard restored, same command:

  Caused by: java.lang.IllegalStateException: northstar.integration.api-key still holds the unresolved placeholder ${NORTHSTAR_API_KEY}; set it from the environment before starting prod

  exit=1

With only DB_PASSWORD missing:

  Could not resolve placeholder 'DB_PASSWORD'

That one comes from Environment.getProperty, which throws on an unresolved
placeholder where the binder does not. Two different mechanisms, both stop
startup.


2, ENV test PLUS CLI dev

  SPRING_PROFILES_ACTIVE=test java -Dspring.profiles.active=dev -jar target/lab26-crm-0.0.1-SNAPSHOT.jar

  The following 1 profile is active: "dev"
  profiles=[dev] apiBaseUrl=http://localhost:9090 connectTimeoutMs=2000 apiKeySet=false

The system property wins and the env var is ignored. connectTimeoutMs 2000
rather than test's 100 confirms which file was read.


3, BINDING MISMATCH

  application-test.yml: connect-timeout-ms: 100  ->  connectTimeout: 100

  profiles=[test] apiBaseUrl=http://localhost:9090 connectTimeoutMs=2000 apiKeySet=false

No error and no warning. The renamed key binds to nothing, the field keeps the
base application.yml value of 2000, and the app starts looking healthy. This is
the quietest failure in the lab. Restored, and the value reads 100 again.

5, NO PROFILE SET

  java -jar target/lab26-crm-0.0.1-SNAPSHOT.jar

  No active profile set, falling back to 1 default profile: "default"
  profiles=[] apiBaseUrl=http://localhost:9090 connectTimeoutMs=2000 apiKeySet=false

The banner and getActiveProfiles both say no profile, but application-dev.yml
does load. Confirmed by temporarily putting api-base-url http://dev-probe:9090
in application-dev.yml and running with nothing set:

  apiBaseUrl=http://dev-probe:9090

Same value as an explicit -Dspring.profiles.active=dev run. So
spring.profiles.default: dev in the base file works, and dev is a default
profile rather than an active one, which is why it does not show up in the
banner. Marker removed afterwards.

Blast radius for a real deployment: an unset profile does not get prod. It gets
dev, with dev's H2 URL and DEBUG logging, and none of the prod secret checks
run because ProdSecretsCheck is @Profile("prod").


6, OVERRIDE LADDER (step 6, full path)

Measured on northstar.integration.connect-timeout-ms under the test profile.
Each run keeps the previous run's setting in place.

  java -jar ... --spring.profiles.active=test
  connectTimeoutMs=100

  NORTHSTAR_INTEGRATION_CONNECT_TIMEOUT_MS=9999 java -jar ... --spring.profiles.active=test
  connectTimeoutMs=9999

  NORTHSTAR_INTEGRATION_CONNECT_TIMEOUT_MS=9999 java -Dnorthstar.integration.connect-timeout-ms=1234 -jar ... --spring.profiles.active=test
  connectTimeoutMs=1234

CLI beats env beats profile YAML beats base YAML at 2000. The env var name is
the relaxed-binding form of the property, upper case with dots and dashes as
underscores.
